# DR0004: Known exception may escape

## Summary

A known, non-allowed exception should not escape a function returning `Result<TValue, TError>`, `Task<Result<TValue, TError>>`, or `ValueTask<Result<TValue, TError>>`.

## Details

Expected failures should be returned through the Result error channel. This rule reports exceptions that are known from:

- Explicit `throw` statements and expressions
- Invoked methods with XML-documented exceptions
- Object creation with XML-documented constructor exceptions
- Property access with XML-documented exceptions

The rule does not attempt to infer undocumented exceptions, exceptions from implicit language operations, or exceptions that arbitrary runtime operations could produce.

When `Darp.Results` is consumed as a NuGet package, its build-transitive target supplies XML documentation files shipped beside resolved references to the analyzer. Documented exceptions therefore flow across package boundaries when the referenced package includes its XML documentation file.

An exception is not reported when it is caught by a compatible, unfiltered catch clause before it leaves the Result-returning function.

For a method returning `Task` or `ValueTask`, the catch clause must surround the directly awaited call. Calls followed by `ConfigureAwait` are also recognized. The analyzer does not track a task stored in a variable to a later `await`, so such calls are reported conservatively.

## Default allowed exceptions

The following exception types and their derived types are allowed by default:

- `System.ArgumentException`
- `System.OperationCanceledException`
- `System.NotImplementedException`
- `System.NotSupportedException`
- `System.Diagnostics.UnreachableException`
- `System.ObjectDisposedException`
- `System.Runtime.CompilerServices.SwitchExpressionException`

## Examples

### Noncompliant

```csharp
Result<string, ReadError> Read(string path)
{
    return File.ReadAllText(path);
    // IOException and UnauthorizedAccessException are documented by File.ReadAllText.
}
```

```csharp
Result<int, Error> Calculate()
{
    throw new InvalidOperationException();
}
```

### Compliant: return the failure

```csharp
Result<string, ReadError> Read(string path)
{
    try
    {
        return File.ReadAllText(path);
    }
    catch (IOException exception)
    {
        return ReadError.From(exception);
    }
}
```

### Compliant: declare the exception contract

An XML exception declaration permits the exception within that function. Result-returning callers that invoke the function will still be warned unless they catch or declare the exception themselves.

```csharp
/// <exception cref="IOException">The file could not be read.</exception>
Result<string, ReadError> Read(string path)
{
    return File.ReadAllText(path);
}
```

Documenting a base exception type permits derived exception types. Documenting `System.Exception` permits all exceptions for that function.

## Code fix

For an editable named method or property, **Document escaping exceptions** adds empty XML exception elements to the declaration:

```csharp
/// <exception cref="System.IO.IOException"></exception>
Result<string, ReadError> Read(string path) => File.ReadAllText(path);
```

No fix is offered for lambdas or local functions because they cannot expose an XML documentation contract.

## Configuration

### Severity

Disable the rule globally or for an `.editorconfig` section with:

```ini
dotnet_diagnostic.DR0004.severity = none
```

### Allowed exception types

Set a semicolon-separated list of fully qualified exception type names:

```ini
dotnet_diagnostic.DR0004.allowed_exception_types = System.ArgumentException;System.OperationCanceledException;System.NotImplementedException;System.NotSupportedException;System.Diagnostics.UnreachableException;System.ObjectDisposedException;System.Runtime.CompilerServices.SwitchExpressionException;MyCompany.ExpectedException
```

When configured, this option replaces the default list. Configuring `System.Exception` allows every exception.

Normal Roslyn suppressions such as `#pragma warning disable DR0004`, `SuppressMessageAttribute`, and `NoWarn` are also supported.
